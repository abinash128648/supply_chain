# Supply Chain Fraud Detection and Recall

A small Python demonstration of a hash-linked supply-chain ledger with rule-based fraud checks, transfer anomaly detection, and batch recall tracing. It includes a Flask API and a browser dashboard.

## Features

- Append-only JSON ledger with SHA-256 block hashes and previous-block links
- Ledger integrity verification for modified blocks or broken links
- Rule validation for duplicate batch IDs, overselling, missing input batches, adulteration, and backdated transfers
- Isolation Forest anomaly detection for suspicious transfers after enough normal transfer history exists
- Permanent `ALERT` records for rejected events and `FLAG` records for anomalous accepted transfers
- Batch genealogy and recall tracing across processed and transferred batches
- Live dashboard for ledger entries, evidence, holdings, integrity status, and recalls

## Project Structure

| File | Purpose |
| --- | --- |
| `supplychain.py` | `Chain` ledger and `Tracker` state, validation, anomaly, and recall logic |
| `detector.py` | Haversine distance and Isolation Forest transfer anomaly detection |
| `api.py` | Flask REST API and dashboard server |
| `dashboard.html` | Browser dashboard |
| `demo.py` | End-to-end demonstration, including fraud attempts and tampering |
| `test_supplychain.py` | Pytest unit tests |
| `demo_chain.json` | Ledger generated by `demo.py` |
| `requirements.txt` | Python dependencies |

## Installation

From the project directory:

```bash
python3 -m venv venv
source venv/bin/activate
python -m pip install -r requirements.txt
```

On Windows, activate the environment with:

```powershell
venv\Scripts\activate
```

## Run the Demo

```bash
python demo.py
```

The demo creates or resets `demo_chain.json`, submits normal and suspicious events, prints recall results, and deliberately modifies a block near the end so that the final integrity check demonstrates tamper detection.

## Start the Dashboard

```bash
python api.py
```

Open <http://localhost:5000>.

By default, the API uses `chain.json`. To use or create a different ledger file:

```bash
CHAIN=demo_chain.json python api.py
```

On Windows PowerShell:

```powershell
$env:CHAIN="demo_chain.json"
python api.py
```

The dashboard refreshes every five seconds and shows:

- Chain block and batch counts
- Alert and anomaly flag counts
- Ledger integrity status
- Current holders of each batch
- Processing parent relationships
- Recall results

Click a batch or fraud evidence row to start a recall.

## Event Format

Supply-chain events are JSON objects and can be submitted through `POST /event`.

Common fields:

| Field | Required | Description |
| --- | --- | --- |
| `type` | Yes | `HARVEST`, `PROCESS`, or `TRANSFER` |
| `batch` | Yes | Batch identifier |
| `actor` | Yes | Person, farm, facility, or organization responsible |
| `qty` | Yes | Quantity for the event |
| `lat` | Yes | Latitude at the event location |
| `lon` | Yes | Longitude at the event location |
| `ts` | No | Unix timestamp; defaults to the server time |
| `temp` | For anomaly detection | Temperature associated with a transfer |
| `to` | For `TRANSFER` | Recipient actor |
| `inputs` | For `PROCESS` | Existing batch IDs consumed as inputs |

### Harvest example

```json
{
  "type": "HARVEST",
  "batch": "FARM-A-1",
  "actor": "farm-A",
  "qty": 100,
  "lat": 18.52,
  "lon": 73.85,
  "temp": 4,
  "ts": 1700000000
}
```

### Transfer example

```json
{
  "type": "TRANSFER",
  "batch": "FARM-A-1",
  "actor": "farm-A",
  "to": "plant",
  "qty": 100,
  "lat": 19.07,
  "lon": 72.87,
  "temp": 4,
  "ts": 1700014400
}
```

### Processing example

```json
{
  "type": "PROCESS",
  "batch": "SAUCE-1",
  "actor": "plant",
  "inputs": ["FARM-A-1", "FARM-B-1"],
  "qty": 150,
  "lat": 19.07,
  "lon": 72.87,
  "temp": 4,
  "ts": 1700028800
}
```

Submit an event:

```bash
curl -X POST http://localhost:5000/event \
  -H 'Content-Type: application/json' \
  -d '{"type":"HARVEST","batch":"FARM-A-1","actor":"farm-A","qty":100,"lat":18.52,"lon":73.85,"temp":4}'
```

The response is one of:

- `accepted`
- `flagged`
- `rejected: <reason>`

## REST API

| Method | Endpoint | Response |
| --- | --- | --- |
| `GET` | `/` | Dashboard HTML |
| `POST` | `/event` | Submit an event JSON body |
| `GET` | `/chain` | Complete append-only block list |
| `GET` | `/state` | Integrity, counts, batches, parents, and holdings |
| `GET` | `/recall/<batch>` | Derived batches and where remaining stock is held |
| `GET` | `/verify` | First tampered block index, or `null` when intact |

Example API calls:

```bash
curl http://localhost:5000/state
curl http://localhost:5000/verify
curl http://localhost:5000/recall/FARM-A-1
curl http://localhost:5000/chain
```

## Validation and Detection

### Rule-based checks

The tracker rejects and records an `ALERT` when:

- An existing batch ID is reused by a harvest or processing event
- A processor does not hold every listed input batch
- Output quantity exceeds input quantity
- A transfer quantity exceeds the actor's current holdings
- A transfer timestamp is earlier than the batch's previous event

Rejected events are evidence records; they do not modify batch holdings or processing state.

### Anomaly detection

Transfer behavior is compared using:

- Transferred quantity
- Transit time in hours
- Implied speed from great-circle distance and transit time
- Temperature

The model starts training after at least 30 normal transfer feature rows. Before that, transfers remain available for rule-based validation. An anomalous accepted transfer is written to the ledger as a `FLAG` block but remains applied to the supply-chain state.

## Ledger Integrity

Every block stores:

- `index`
- `ts`
- `data`
- `prev`
- `hash`

The SHA-256 digest covers `index`, `ts`, `data`, and `prev` with JSON keys sorted before hashing. `Chain.verify()` returns the first block whose hash or previous-block link is invalid; it returns `None` when the chain is intact.

## Recall Example

To find all batches derived from a contaminated batch:

```bash
curl http://localhost:5000/recall/FARM-A-1
```

The response includes the source batch and every processing descendant. Positive quantities are grouped by the actor currently holding each batch. Consumed or shipped stock may appear as an empty holder map.

## Tests

Run the complete test suite:

```bash
source venv/bin/activate
pytest -q
```

The tests cover valid events, duplicate IDs, overselling, missing holdings, backdated events, adulteration, anomaly flags, recall tracing, tamper detection, and state rebuilding from JSON.

## Notes

- This project is a local educational prototype, not a distributed blockchain.
- Ledger state is stored in a single JSON file with no identity, authentication, or access control.
- `ALERT` and `FLAG` entries are evidence blocks and are not modeled as normal inventory events.
- `CHAIN` can point to a demo or test ledger, but only one process should write to a ledger file at a time.
